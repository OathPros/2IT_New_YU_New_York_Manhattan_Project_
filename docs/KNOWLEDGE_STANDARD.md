# Knowledge standard

Use one article for one reusable task or one issue and resolution in a specific environment. Service descriptions and eligibility remain service information. Policies and standards remain resources

| Content field | Halo presentation |
| --- | --- |
| title | Title |
| type | Article Type |
| issue and environment and optional cause | Description |
| resolution_html | Resolution |
| source_urls and capture information | Migration provenance |
| state and reviewed_at | Confidence and review evidence |

Use the requester’s task or symptom, precise products and versions, and ordered actionable steps. Only state a cause when the source supports it. Split different resolutions for different environments. Reuse maintained vendor documentation and link related knowledge instead of duplicating it

Imported material starts not_validated. Capturing a page is not a review. Do not invent owners, validation dates, causes, or usage counts

The full page and popup share one renderer and one article record. Native dialogs provide Escape dismissal, keyboard containment, and focus restoration. Direct article URLs work without JavaScript

Use content/editorial-overrides.json to rewrite content while retaining provenance and permanent slugs. Set state to validated only after a real review with reviewed_at evidence
