Inspect the local repository, data, URLs, deployment constraints and actual rendered baseline. Preserve valuable content, stable identifiers, routes, verified support links and functional integrations; replace restrictive public presentation architecture where justified. Keep the current live deployment untouched.

Use Anthropic and IBM Design for editorial composition and institutional sophistication, Linear for interaction precision, Apple Support for task-first technical guidance. Use actual reference screenshots if available; if blocked, report the gap, never claim to have reviewed them. Develop distinct visual concepts for homepage and Passport York, select based on task clarity and product character, and implement the chosen vertical slice before scaling. Avoid generic SaaS cards, pill overload and gratuitous decoration. Make mobile equally intentional.

Unify service discovery, actions, knowledge and support through the existing service information model. Inspect actual entities and relationships before proposing changes. Use contextual eligibility, operations, guidance and dependencies. Preserve standalone knowledge URLs and contextual support, with a direct human-support path. Test natural-language queries such as lost phone, cannot log in and connect to Wi-Fi; use deterministic search if no semantic infrastructure exists. Do not fabricate institutional claims, account recovery, service status, AI or ticket submissions. Label unverified content. Prepare future NEXUS and Halo integration seams without claiming existing connections.

Apply the successful pattern across homepage, search, catalogue, representative offering types, knowledge and support. Capture desktop/mobile screenshots and exercise core journeys. Run existing build/tests and add targeted regression, relationship and accessibility checks where appropriate. Deliver the implemented local preview and evidence, not merely a design plan. Independent review before release. No push/merge/deploy without approval.
