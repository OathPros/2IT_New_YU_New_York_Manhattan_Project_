# Visual direction exploration

Generated by `node .devkit/concepts/generate.mjs`. It renders into `dist/_concepts/` using the real service model: journeys, 33 Passport York articles, offerings and ontology relations. Captures are in `.devkit/artifacts/concepts/` (gitignored), taken at desktop 1440 and mobile 390.

| | A Editorial | B Precision console | C Guided support |
| --- | --- | --- | --- |
| Reference | Anthropic, IBM Design | Linear | Apple Support |
| Character | Warm paper, large Plex Light and SemiBold display, mono labels, label column plus content grid, hairline rules | Dark, command palette hero, three-pane service workspace with properties rail | White, centred, icon row, rounded tiles, numbered red discs |
| Strengths | Most distinctive and York-appropriate. Strong hierarchy. Numbered task index reads as a product rather than a directory. Long lists stay calm | Shows service intelligence directly: eligibility, knowledge state, relationships and schedule beside the task. The palette demonstrates intent search | Most familiar. Explicit "Which York account do you have" choice is very clear |
| Weaknesses | Duplicate student and employee titles are indistinguishable without audience labels. Few direct actions on home. Label column wastes space on mobile | Dark UI is poor for long-form knowledge reading, print and institutional brand. Grey-on-black secondary text is close to contrast limits | Generic rounded card grid (a rejected pattern). Centred text harms scanning of long guidance. Weak brand expression |

## Decision

Selected direction: **A Editorial foundation with B interaction patterns and C's explicit audience choice.**

- From A: paper and charcoal palette, Plex weight contrast, the index grid (mono label column plus content), numbered task rows, hairline rules instead of boxes.
- From B, translated to the light theme:
  - instant command search with grouped results and keyboard navigation
  - a service workspace properties rail with eligibility, connected services, knowledge state, schedule and sources
  - compact mono "needs" tags
- From C: an explicit audience question at the start of each journey with large selectable options.
- Fix A's weaknesses: audience labels on every knowledge row, a quick actions strip on home, and the label column collapses above content on mobile.

Rejected: the full dark theme from B, and the rounded tile grid and centred long-form layouts from C.
